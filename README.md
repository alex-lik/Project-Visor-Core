# 🛰️ Project Visor Core — Open-Source Developer Control Plane, Infrastructure Matrix & OpenCode Hub

[![License: AGPL v3](https://img.shields.io/badge/License-AGPL_v3-blue.svg)](LICENSE)
[![TypeScript](https://img.shields.io/badge/TypeScript-5.8-blue?logo=typescript)](https://www.typescriptlang.org/)

[![Docker](https://img.shields.io/badge/Docker-Ready-2496ED?logo=docker)](https://www.docker.com/)

**Project Visor Core** — это полнофункциональный открытый командный центр (*Developer Control Plane*) для разработчиков, DevOps-инженеров и Homelab-энтузиастов. 

Visor Core позволяет объединить в едином интерфейсе физические серверы, VPS и локальные машины, управлять жизненным циклом разнородных проектов (боты, веб-приложения, API, микросервисы, скрипты), настраивать профили мульти-контейнерного деплоя, автоматически предотвращать сетевые конфликты портов, визуализировать топологию архитектуры связей и исполнять задачи прямо на удаленных серверах через **OpenCode Server**.

---

## 🌟 Возможности Core

* **🖥️ Единый реестр серверов и Homelab**:
  * Учет VPS (Hetzner, DigitalOcean, AWS, Timeweb) и физических серверов.
  * Управление SSH-алиасами, пользователями и портами.
  * Мониторинг статуса хостов (`online`, `degraded`, `offline`).
* **📦 Мульти-контейнеры и автоматический детектор конфликтов портов**:
  * Неограниченное число контейнеров на проект с типизацией (`web`, `api`, `database`, `cache`, `worker`, `queue`, `proxy`, `cron`).
  * Поддержка сетевых протоколов (`http`, `https`, `tcp`, `udp`, `grpc`, `ws`).
  * Сканирование хоста в реальном времени с мгновенной подсветкой конфликтов занятых портов.
* **⚡ Нативная интеграция с OpenCode Server**:
  * Автоматическое сканирование и подключение к OpenCode Server (порты 443, 80, 4096).
  * Динамическое получение доступных моделей с хоста.
  * Запуск промптов и задач прямо в рабочей директории проекта.
  * Интерактивный просмотр сгенерированного Git Diff и сессий.
  * Устойчивость к сетевым задержкам и Cloudflare 524 timeouts с recovery-polling.
* **📋 Двухуровневый Канбан & Радар фокуса**:
  * Канбан-доска внутри каждого проекта (`Бэклог`, `To Do`, `В работе`, `Review`, `Выполнено`).
  * Глобальный «Радар фокуса» на дашборде с задачами «В работе» по всем проектам.
* **🕸️ Интерактивный граф архитектуры (Service Topology)**:
  * Визуализация взаимосвязей между микросервисами (`depends_on`, `api_calls`, `database_shared`, `webhook_events`, `auth_provider`, `submodule`).
  * Перетаскивание узлов, масштабирование и фильтрация.
* **🔐 Безопасность и Scoped API Токены**:
  * Локальная аутентификация (хэширование bcryptjs, JWT-сессии).
  * Гранулярные API-ключи с ограничением прав на проекты (`canWriteKanban`, `canUpdateStatus`, `canViewInfra`).
  * Аудит всех действий в платформе (`activity_logs`).

## 🚫 Чего нет в Core (Границы открытого ядра)

Project Visor Core ориентирован исключительно на базовую универсальную функциональность управления проектами и инфраструктурой. 

В открытое ядро **не входят** и доступны в расширенной коммерческой версии:
* Сторонняя проприетарная AI-оркестрация и фоновый цикл Autopilot.
* Встроенный сервер Model Context Protocol (MCP) со специфическими инструментами.
* Интеграции с Telegram-ботом и SMTP Email-алертами.
* Платёжные шлюзы, подписки и реферальная программа.
* 1-клик облачный провижининг серверов и закрытое хранилище токенов Cloud Vault.
* Каталог партнерских офферов экосистемы.

Core полностью автономен: он не делает сетевых запросов во внешнюю коммерческую инфраструктуру и не требует закрытых API-ключей.

## 🚀 Быстрый старт

### Вариант 1: Локальный запуск (Node.js)

1. **Клонируйте репозиторий**:
   ```bash
   git clone https://github.com/alex-lik/Project-Visor-Core.git
   cd Project-Visor-Core
   ```

2. **Установите зависимости**:
   ```bash
   npm install
   ```

3. **Инициализируйте базу данных и демо-стенд**:
   ```bash
   npm run db:seed
   ```
   *Создает локальную SQLite базу данных `data/visor.db` и администратора `admin` с паролем `admin123`.*

4. **Запустите сервер разработки**:
   ```bash
   npm run dev
   ```
   Откройте в браузере: **`http://localhost:3000`**

---

### Вариант 2: Запуск в Docker Compose

```bash
docker compose up -d --build
```
Project Visor Core поднимется на порту `3000` с сохранением базы данных в локальном томе `./data`.

## ⚙️ Конфигурация (.env)

Core использует минимальный набор переменных окружения. Создайте `.env` на основе `.env.example`:

```env
PORT=3000
NODE_ENV=production

# Секретный ключ для подписи сессионных JWT токенов
JWT_SECRET=generate-a-strong-secret-key-32-chars-long

# Путь к SQLite базе данных (по умолчанию локальный файл)
DATABASE_URL=file:./data/visor.db

# Опциональный URL Prometheus для сбора метрик серверов
PROMETHEUS_URL=http://localhost:9090
```

## 📖 Руководство пользователя

### 1. Добавление сервера инфраструктуры
1. Перейдите в раздел **«Инфраструктура»** (`/infrastructure`).
2. Нажмите кнопку **«Добавить сервер»**.
3. Укажите имя хоста, IP-адрес, пользователя SSH (root) и порт (22).
4. Если на сервере поднят OpenCode Server, включите переключатель **«OpenCode Server»** и укажите порт (по умолчанию `4096` или `443`).
5. Сервер появится в реестре с мониторингом статуса и быстрым копированием команды подключения `ssh user@ip`.

### 2. Создание проекта и контейнеров
1. Перейдите в раздел **«Проекты»** (`/projects`) и нажмите **«Добавить проект»**.
2. Задайте название, категорию (`Сайты`, `Боты`, `CRM`, `API`, `SaaS`, `Скрипты`) и статус жизненного цикла.
3. Привяжите проект к серверу инфраструктуры.
4. В секции **Контейнеры** добавьте сервисы (например, `web` на порту 3000, `database` на порту 5432).
5. Система мгновенно проверит сервер на конфликты портов: если порт 5432 уже занят другим контейнером на этом хосте, вы увидите визуальное предупреждение.

### 3. Работа с OpenCode Server
1. Откройте карточку проекта и перейдите на вкладку **«OpenCode AI»**.
2. Если к проекту привязан сервер с включенным OpenCode, система автоматически проверит здоровье endpoint.
3. Выберите модель из динамического списка моделей, доступных на вашем хосте.
4. Введите задачу/промпт и нажмите **«Запустить задачу»**.
5. Результаты выполнения и интерактивный **Git Diff** отобразятся в истории запусков.

## 🧪 Запуск автоматических тестов

В Core включены наборы автоматических тестов, проверяющих ключевую логику:

```bash
npm test
```

Список проверок:
1. `test-multi-containers.mjs` — Мульти-контейнеры, типы сетевых протоколов и детектор конфликтов портов.
2. `test-multiuser-and-tokens.mjs` — RBAC-авторизация, выпуск scoped API-токенов и разграничение прав.
3. `test-opencode-integration.mjs` — Проверка протокола OpenCode Server, сессии и запуск задач.
4. `test-opencode-524-recovery.mjs` — Устойчивость к Cloudflare 524 timeout и целостность связей при удалении хостов.

## 🏛️ Архитектура Core

```
Project-Visor-Core/
├── src/
│   ├── app/                 # Next.js App Router (страницы и API роуты)
│   │   ├── api/             # Внутренний REST API ядра
│   │   ├── infrastructure/  # Интерфейс серверов и портов
│   │   ├── projects/        # Каталог проектов и карточка проекта
│   │   ├── tasks/           # Канбан доска
│   │   ├── graph/           # Архитектурный граф
│   │   └── settings/        # API ключи и пользователи
│   ├── components/          # Reusable UI компоненты и модальные окна
│   ├── views/               # Экспортируемые полноэкранные View компоненты
│   ├── db/                  # SQLite клиент и Drizzle ORM схема
│   └── lib/                 # Модули бизнес-логики:
│       ├── opencode.ts      # Клиент OpenCode Server
│       ├── containers.ts    # Конфликт-детектор портов и контейнеры
│       ├── notifications.ts # Интерфейс NotificationProvider
│       ├── auth.ts          # JWT и bcrypt аутентификация
│       └── rbac.ts          # Ролевая модель и проверка прав
├── scripts/                 # Тесты ядра и утилиты
├── docker-compose.yml       # Docker Compose стенд
├── Dockerfile               # Мультистейдж образ
└── README.md
```
